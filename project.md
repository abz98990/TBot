# NEURAL TRADING BOT v3.0

## 🎯 Project Goals
The goal of this project is to build a highly autonomous, robust, and profitable AI-driven algorithmic trading bot for cryptocurrency markets. It leverages a PyTorch LSTM (Long Short-Term Memory) neural network with real-time continuous calibration (online learning) to adapt to shifting market regimes. It operates completely autonomously, tracking multiple coins in parallel, executing trades on Binance, and visualizing performance in real-time.

---

## 🏗️ Current Architecture

The project is structured into modular components, glued together by an asynchronous main loop.

1. **`main.py` (The Async Router)**
   - Spawns independent parallel tasks (`asyncio`) for multiple crypto pairs (e.g., BTC/USDT, ETH/USDT).
   - Manages state persistence (`bot_state.json`) and prediction queues to survive reboots.
   - Handles the 4-candle position management (trades are held for exactly 4 candles, then closed).
   - Uses a **Split-Exchange Setup**: Fetches data from Binance Mainnet (for deep history) but executes paper trades on Binance Testnet.

2. **`module_1_data.py` (Data Streamer)**
   - Uses `ccxt` to fetch raw OHLCV market data.

3. **`module_2_features.py` (Feature Engineer)**
   - Computes technical indicators: RSI, ATR (normalized), Distance from 50 EMA, MACD, and ADX.
   - Engineers the Target Variable: Predicts the trend 4 candles into the future (`shift(-4)`).
   - Normalizes data using Z-score standardization (tracked via a saved `joblib` scaler).
   - Shapes the 2D pandas dataframe into a 3D Tensor `(samples, window_size=60, features)` for the LSTM.

4. **`module_3_model.py` (Model Engine)**
   - A PyTorch LSTM architecture.
   - Performs *Continuous Calibration*: Retrains itself slightly on every loop iteration using the freshly closed actual outcomes, saving the updated weights to disk.

5. **`module_4_execution.py` (Execution Manager)**
   - Connects to Binance.
   - Calculates Risk Management (dynamic Stop-Loss based on ATR or flat %).
   - Dispatches Market Entry orders and corresponding Stop-Loss layers simultaneously.

6. **`dashboard.py` (Real-Time Visualizer)**
   - A completely decoupled `matplotlib` animated dashboard.
   - Reads dynamically updated CSV logs from `main.py` to plot Asset Price, AI Confidence, Oscillators (RSI/MACD/ADX), and Cumulative PnL/Rolling Accuracy in real-time.

## 🛑 Problems We Faced (And How We Fixed Them)

1. **The 50% Accuracy Wall (Micro-Noise)**
   - *Problem:* The bot originally tried to predict the very next 15-minute candle. It was basically guessing random noise, keeping accuracy pinned at 50%.
   - *Fix:* Upgraded the "Prediction Horizon" to 4 candles into the future. By shifting the target to `shift(-4)` and holding positions for exactly 4 candles, the AI is forced to learn the macro-trend rather than high-frequency noise.

2. **Binance `MAX_NUM_ALGO_ORDERS` Limit Reached**
   - *Problem:* When the bot was restarted manually while holding an active position, it lost its memory of the trade but left the Stop-Loss active on Binance. Repeated restarts caused 10 "ghost" Stop-Loss orders to stack up, locking the account.
   - *Fix:* Implemented a State Persistence engine (`bot_state.json`) in `main.py` that writes the active position to disk. On reboot, the bot seamlessly reloads the position and resumes managing the Stop-Loss.

3. **Dashboard Rendering Glitches (Massive Blocks & Broken Lines)**
   - *Problem:* The live dashboard broke when old CSV rows were manually deleted, causing massive gaps in the timeline and stretching 3 data points across a 60-point axis.
   - *Fix:* Engineered a rolling history queue in memory. Now, on every single tick, `main.py` instantly rewrites the entire 100-tick history into the CSV from scratch. The dashboard reads this flawlessly and even retroactively fills in pending accuracy data as 4-candle predictions mature!

4. **`pandas_ta` Internal Crash on Testnet Data**
   - *Problem:* The open-source `pandas_ta` library randomly failed when computing the 50 EMA, returning the raw DataFrame instead of a Series. This caused a `Cannot set a DataFrame with multiple columns` crash.
   - *Fix:* Ripped out the buggy `pandas_ta.ema` implementation and replaced it with Pandas' highly stable, native exponential math (`df.ewm()`).

5. **Tensor Shape `(0,)` & Division By Zero**
   - *Problem:* Binance Testnet routinely wipes historical data. Requesting 500 1-hour candles only returned 35 candles. After dropping NaNs generated by MACD (26+9 periods), the DataFrame shrank to 0 valid rows. It was mathematically impossible to form a 60-candle tensor window, crashing the model.
   - *Fix:* Implemented the **Split-Exchange Architecture**. `DataStreamer` now connects to Binance Mainnet (public endpoints) to securely fetch thousands of flawless historical candles, while `ExecutionManager` independently connects to Binance Testnet to execute paper trades with the API keys.
